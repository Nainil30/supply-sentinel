# Spec 07 — Planner Console (Streamlit)

Goal: a clean, table-first console a planner would actually use for the weekly review, and the screen used in the 5-minute demo. Tables first; charts only where a trend is the point.

Code: `src/supply_sentinel/app/` — `streamlit_app.py` (entry), `pages/`, `components/`, `services.py` (all data access goes through the engine, the MCP client, or the decision store; no SQL in pages). CLI: `sentinel ui`.

## Pages

| Page | Content | Interactions |
|---|---|---|
| Overview | Snapshot id, as-of date, staleness badge, profile in use. KPI row: open exceptions by type, revenue at risk (shortages), pending LTB spend, E&O exposure, pending approvals. Table of top 10 exceptions by severity | Click a row → Exception detail |
| Exception queue | Sortable, filterable table: id, type, severity, part, platforms, weeks to impact, $ impact, baseline action, agent action, status | Filters by type, severity, platform, status |
| Exception detail | Header card. Evidence tables: projected balance by week (with a small line chart of PAB), open POs, commits (notes shown in a bordered "untrusted text" box with flags), where-used, decision history. Recommendation card: primary/secondary action, quantity, root cause, baseline agree/deviate + reason, alternatives considered, risks, confidence, tier, grounding status (each cited number shows a tooltip with its tool call id). Draft message with copy button. Link to trace | Edit quantity → re-validates before approval |
| Approvals | Pending recommendations grouped by tier, with spend and flags | Approve, Approve with edit (reason required), Reject (reason required). Resumes the LangGraph thread with `Command(resume=…)`. Second-approver flag shown above $50k (demo: a second checkbox) |
| What-if | Pick a part. Controls: slip a PO by N weeks, change demand by % per platform, expedite qty to week, release hold units | Before/after PAB table and line chart via `simulate_scenario` |
| Decisions log | All recorded recommendations and human decisions with filters | Export CSV |
| Evals | Leaderboard, per-category table, latest failures with links to ledgers | Select results file |
| Run | Start a run with a chosen profile and snapshot; progress by node; pending-approval count when it pauses | Disabled for `free-cloud` on the hosted demo |

## Rules

- Every number displayed comes from an engine call, a tool result, or the decision store. No arithmetic in UI code beyond formatting.
- Untrusted text is always rendered as plain text (no markdown/HTML rendering) inside a visibly marked box.
- Works in light and dark themes. Readable at laptop width. No custom JavaScript.
- Hosted demo runs in `replay` mode with a prepared run so approvals and resume work without any key.

## Tests

- Service-layer unit tests (the pages stay thin).
- Streamlit `AppTest` smoke tests: each page renders on the `base` snapshot in replay mode; approve and reject flows update the decision store.
